# Survey source-order safety repair

**Status: PARTIAL.** The source-order failure mechanism is reproduced deterministically in a synthetic Linux API/database workflow; the exact cause of the historical Windows failure remains unproven because its consumed record order and creation-time ties were not captured. This is not a field-validated trajectory calculation or an exact-SHA Windows certification.

## Reproduction and safety boundary

`DdrProcessor._records` orders extracted artifacts by page, `created_at`, and ID. Before this change `_promote_surveys` used that list as though it were the original survey-table sequence. An API upload with source depths 500 then 600 m, but artifact timestamps deliberately arranged in the opposite order, reproduced the historical rejection: zero promoted stations and a non-increasing batch reason. With timestamps deliberately tied and synthetic record IDs deliberately in reverse lexical order, a temporary test plugin restoring the previous query-order behavior again failed the unchanged 2-station assertion. This demonstrates a real, platform-independent failure mechanism, not proof that historical Windows records had those exact timestamps or IDs.

The repaired survey path orders rows by source **page, region order and source row** using the document's existing extraction evidence links. It requires the record, evidence link and table region to agree on organization, document, region and page; it checks that the full stored source-cell locator list matches exactly one actual region table row. Missing, malformed, duplicated, conflicting or ambiguous coordinates — including distinct regions at the same page/order — hold the batch for human review, never sort by measured depth or use record creation time as source evidence. Source coordinates are indexed once per region and evidence queries are batched. Existing source descent, duplicate-depth, frame/datum and other validation remain in force. Existing station revisions and time provenance rules are unchanged.

## Tests and limits

The 15 new synthetic cases cover LF and CRLF, reversed creation times, tied times with deliberately reversed IDs, retry, explicit timezone-normalized and missing station timestamps, missing evidence, duplicate links/coordinates/region positions, malformed/forged row/cell/region locators, descending and duplicate source depths, and a two-sheet/two-page spreadsheet with repeated source-row numbers. The first explicit station time is UTC `2026-03-15T10:00:00Z`; the second remains null/unknown, never the report period. Focused cases passed 15/15, and the affected ingestion/promotion selection passed 145 tests before the final additional duplicate-region check. Ruff and the CP16 documentation guard passed.

After the final source and test edits, a complete local SQLite run passed **1,808 with 15 PostgreSQL skips**, and a complete local embedded-PostgreSQL-enabled run passed **1,823 with one environment warning**. Both final runs passed the reviewed test inventory. Two earlier concurrent suites each passed their then-collected 1,822 tests (SQLite: 1,807 + 15 skips; PostgreSQL-enabled: 1,822), but their inventory verifiers failed because the manifest was updated to 1,823 while they were running; those earlier verifier failures are not hidden or treated as final acceptance. None of these Linux results establish native Windows or field acceptance.

[CI run 44877582728](https://github.com/asgareyvazi/DrillAI/actions/runs/44877582728) on fix commit `8f013ebb6912d11fc45d5b948af2e7d781ae42e8` passed native Windows backend **1,807 passed, one skipped, 15 deselected** and Linux PostgreSQL-enabled backend **1,823 passed**. Both standard browser suites passed 128/128 with zero retries, and both supply-chain checks passed. Overall CI was **failed** by the independent deployment-image CP135 OCR gate; later commits require their own CI.

Older records without adequate scoped evidence are deliberately held for review, including single rows; this can reduce automatic promotion and is preferable to inventing source order. Some formats may not retain table row locators and will therefore require review. This behavior does not establish source authenticity or independently verify OCR/engineering measurements. Broader source-format/large-document tests, field review and historical-failure causality remain open.
