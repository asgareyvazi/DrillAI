## Safe evaluation path

A future authorized evaluation needs a legitimately obtained, revision-pinned checkpoint and tokenizer, cryptographic hashes, reviewed model and upstream license terms, a supported local runtime, memory/disk sizing and an isolated non-confidential dataset. Record hardware, inference parameters, runtime version, actual latency and memory, failures and all case outcomes. Compare against a meaningful smaller local baseline on independent holdouts for scoped source retrieval/citation correctness, abstention with missing or conflicting inputs, bilingual queries, prompt injection and reference-based engineering tasks. Freeze the protocol and thresholds before looking at outcomes; distinguish model-generated narration from calculations executed by registered engines. Do not treat publisher metrics as measured results or send confidential documents to a remote service without policy authorization.

The existing provider registry allows an explicitly selected Ollama endpoint without a public-cloud key and enforces configured privacy ceilings (`backend/src/drillai/ai/providers.py`, `backend/src/drillai/core/config.py`); this source inspection is not proof that any particular OGAI model loads, responds correctly, or fits the deployment. Stub provider behavior remains labeled as such. The model must not invent inputs/citations, replace registered-engine arithmetic, approve a draft or operate a rig.
