# Runtime engine metadata snapshot

**Status: PARTIAL.** The machine-readable [metadata snapshot](CONTINUOUS-ENGINE-DECLARED-METADATA.json) records all 14 registered engines observed at source revision `80cd5eca853d81746658b4b4a556b8704e386b0c`, with implementation function and file, model names, self-declared validation status, assumptions, limitations, references and a reduced schema-level unit declaration. It contains 194 input paths and 291 output paths, including declared unknown states; these are schema paths, not evidence that every path was executed. Snapshot SHA-256: `7a99d2c1369c4dccedc846035bd55564c0aff0b9f96e5cb49ad44eb6133cbc9b`.

The contents are transcribed from `EngineSpec` and `spec.describe()["unit_contract"]`, not independently checked against the cited publications. `formula_derived` is a registry classification, not evidence of independent validation. `tubulars.api_5c3` and `well_control.kill_sheet` retain `needs_field_validation`. This is neither a complete historical or proposed-future engine inventory nor a safety/range/equation audit; it does not establish correctness of metadata, unit conversion, references or output. Display-unit transformation details and full Pydantic schemas are intentionally omitted; the source's `EngineSpec.describe()` remains authoritative for its declared schema contract.

To reproduce the extraction at the cited revision, load `load_default_engines()`, iterate sorted registry keys, take each registered `FunctionEngine`'s `_fn` module/function and `spec` declarations, and reduce each `input_fields`/`output_fields` unit-contract item to `status`, `value_unit`, `dimension`, `canonical_unit`, `unknown_reason`. The snapshot was produced from the checked-out source, not from external vendor software. As this uses private adapter `_fn`, another future engine adapter could require a different provenance inspection; do not interpret this technique as exhaustive for plugins.

Remaining catalogue work: map each equation to reviewed, accessible independent reference examples and units; collect exact API/UI/workflow call paths, meaningful per-engine tests and failure behavior; reconcile historical and proposed future engines; assess numerical range, uncertainty and field suitability. An unverified bibliographic title remains an unverified declaration, not a source-validated equation.
