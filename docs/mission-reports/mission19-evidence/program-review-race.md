# Program review/withdrawal concurrency increment

A deterministic file-backed SQLite API test pauses withdrawal after it reads the pending approval, commits an independent review in a separate request, and resumes withdrawal. The original implementation returned success but overwrote the just-committed review in the approval payload; `program-lost-review-before.txt` preserves the failure. The earlier harness attempt timed out because middleware changed asyncio task identity; that initial diagnostic is retained separately.

Withdrawal now compares the persisted reviewer and review timestamp with its snapshot during its revision update. If the review changed, the transaction rolls back the earlier approval update and returns HTTP 409; a subsequent retry sees and archives the review. A fault injected at audit persistence also verified rollback and retry. Additional API tests exercise competing withdrawal/decision, withdrawal/review and duplicate withdrawal. A PostgreSQL API test used separate requests and a real held review lock; after review committed, withdrawal preserved its history. The local PostgreSQL pgvector integration and synthetic CP150 browser scenario also passed. These results do not prove every interruption, retry or multi-process execution, and the CP150 scenario is not field acceptance.
