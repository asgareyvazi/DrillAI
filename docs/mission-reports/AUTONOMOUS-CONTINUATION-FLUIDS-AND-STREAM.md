## Reproduced failures and changes

At source `d41e387780c6ce37397bc4f5337c3738c200ad65`, for a synthetic Newtonian pipe (ID 0.005 m, flow 0.02 m³/s, PV 0.02 Pa·s) the fixed solver returned 10,000,000 Pa/m; independent Poiseuille `128 μ Q/(π D⁴)` gives approximately 26,075,946 Pa/m. This extreme input demonstrates a numerical boundary failure, **not a valid turbulent pressure prediction**. The same implementation also silently replaced zero/missing PV with a fabricated value. Test cases failed before the repair.

`hydraulics.laminar` 1.3.0 now requires explicitly supplied positive PV, searches for a genuine bracket in both directions, uses algebraically factored Bingham flow relations to reduce cancellation near yield, checks the recovered flow and rejects unrepresentable/nonconverged results with `engine.convergence_failed`. Tests check independent Newtonian closed forms above the old upper bound and below the old lower bound, Bingham implicit flow relations, and a numerical failure. Regime warnings and the non-certified turbulent status remain; this is still a laminar model, not a new turbulent model. Other numerical and geometry paths are not exhaustively audited; especially missing hydraulic interval geometry and the existing warned MD-as-TVD fallback need further review before operational use.

`wellbore.capacity` 1.2.0 now rejects an unknown bore, a coverage gap from surface to requested bit depth, or a pipe that does not fit before computing bottoms-up values. Synthetic tests compare a multi-segment volume and time with the independent cylindrical-volume formula, and exercise four previously accepted incomplete/impossible geometries. Full-model volumes outside the bottoms-up interval can still be incomplete; nominal concentric geometry, the largest inner OD assumption, no washout and other declared limitations remain. A well with no declared inner element is treated as an open bore, not evidence that no equipment exists. Historical stored runs are not recalculated and preserve their engine version.

The existing generic engineering UI, `/registry/engines/{key}/run` API and scoped stored run history expose version, input/output hashes, units, warnings, assumptions and results. A synthetic API integration regression checks both versions, independent reference values, audit readback and that the two tested invalid inputs do not create new run records. This exercises pre-existing integration, not a new dedicated workflow, independent engineering sign-off or end-to-end UI proof for each engine.

A separate deterministic frontend regression showed a changed REST event cursor recreated the live socket (two sockets instead of one), even when the run/identity had not changed. The hook now advances the cursor without recreating the socket, and still replaces it on run/identity change. This is an independently reproduced churn defect; **it is not proven to cause Windows `ERR_NO_BUFFER_SPACE`**. REST remains authoritative, the stream still closes on run/identity changes and no error oracle, timeout or retry setting was weakened.
