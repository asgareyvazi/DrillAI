## 3. Current CP25/CP26/CP31/CP32 Release-Candidate Snapshot (2026-10-24)

**Active session branch:** `arena/9d8f5568-drillai`. CP25 source `9c5db2f45d6c489aaf87392892b82cd8438cb684` and evidence tip `c01fa06aebd1badc4860c462e1483d680e67c6ea` are published, followed by CP26 tip `c6453c6f4550fb13b445df9c96b270448dd68dbb`, CP31 tip `919da0f41e3597368bc145a7532d2f132d66c1c5` and the CP32 tip published with this snapshot.

**GitHub Actions run `39563150524`** executed the exact CP31 SHA `919da0f` on 2026-10-21. The Linux `certification` job (`119098935547`) **PASSED**, including the corrected Docker Compose deployment gate and the complete Playwright E2E suite. The `windows-certification` job (`119098935468`) **FAILED** at the Playwright E2E step: **115 passed, 6 failed**, every failure in `frontend/e2e/workflow-studio.spec.ts` on the shared `expect(consoleErrors).toEqual([])` assertion.

That Windows failure was **not** a regression from CP31: the `windows-certification` job is byte-identical between the CP26 tip `c6453c6` (Windows passed) and the CP31 tip `919da0f`, and the CP31 diff touches no file under `frontend/` and none under `backend/src/`. The cause was the oracle, not the product: the journey judged the **browser's** network log, and Chromium writes a cancelled request differently on different runners — `net::ERR_ABORTED` on Linux, a dropped connection on Windows — so a routine cancellation of the application shell's background reads failed six journeys on one platform and none on the other. The studio's own API calls were instrumented and **every one returned 200** except the single refusal a journey provokes on purpose. The contract is corrected and guarded in **CP32** (`CP32-E2E-PLATFORM-INDEPENDENT-VERDICT.md`).

The earlier Linux deployment-gate failure (run `39414613792`, job `118600471494`, exit code 22) was a malformed probe, not a deployment defect: the gate sent `curl -fsSI` (**HEAD**) against `/api/v1/health/ready`, which FastAPI registers for `GET` only, so the request was answered with `405` and `curl -f` reported exit code 22. The defect was reproduced locally and is corrected and guarded in **CP31** (`CP31-CI-DEPLOYMENT-PROBE-CONTRACT.md`); the corrected gate **passed** on `919da0f` in run `39563150524`.
