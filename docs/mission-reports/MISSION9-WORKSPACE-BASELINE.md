# Mission 9 workspace baseline and disposition

The raw initial Git state and filesystem inventory are in MISSION9-GIT-START.txt and MISSION9-WORKSPACE-START.jsonl. The inventory excludes `.git` internals, never follows symlinks and describes the workspace immediately before the two Mission 9 capture files were created. It hashes regular files, not itself; classification is relative to the starting index and Git ignore rules. Directory metadata is also captured. This is a snapshot, not a claim about historical file creation.

The three untracked `MISSION8-FINAL-CI.json`, `MISSION8-GIT-END.txt`, `MISSION8-WORKSPACE-END.jsonl` were created by the previous mission, identified by its recorded end-state and contents. They are durable evidence and are committed in this phase. The five untracked historical evidence files under the four protected directories predate Mission 9 and are user-protected; they are neither deleted nor added to Git. Their five hashes match the specified historical hashes; preserve the nine file/directory entries' Mission 9 starting metadata. Their mtimes already differed at Mission 8 start from Mission 7 end; the cause and original restoration are unknown. The four Mission 4 `.e2e-m4-*` paths and original `frontend/dist` remain missing; no restoration is claimed.

`backend/.data/` and `backend/.data/blobs/` are ignored empty directories observed at Mission 9 start. Mission 8's test run created them, but their current ownership and any external significance are not independently verifiable; they are preserved. No ignored regular files were found in the repository snapshot. `/tmp/drillai-mission8` is previous-mission scratch, outside the repository: it contains isolated virtual environments and npm dependencies, browser binaries/caches, test databases and traces, Git/CI logs and OCR diagnostics. These were retained, not deleted; durable Mission 8 OCR data and CI summaries are in the repository. `/tmp/drillai-mission9` is the new scratch area. No other worktree, stash, tag or submodule was reported. No cleanup of unknown artifacts was performed.

The end manifest and raw Git state will have an explicit self-reference policy. A tracked manifest cannot contain its own final hash or the hash of the commit which contains it; exact final SHA and CI are separately discoverable in GitHub and final response. Protected untracked historical evidence is an intentional exception to a clean Git status, not an unexplained file.
