> **Remaining internal gap after CP32 (quantified).** The seven journeys that provoke deliberate failures — `checkpoint5`, `connectors-platform`, `context-deeplinks`, `error-auth`, `error-matrix`, `identity-permissions` and the two `error-faults` journeys — still assert only on `appConsoleErrors(consoleErrors)` and do not assert on the recorded failing responses that `expectNoFailures` uses. They are therefore not yet covered by the platform-independent response oracle; they tolerate the browser's network log but do not prove that a call they did not provoke never failed. Closing it means giving each of those journeys the refusal it provokes as an explicit allowlist — the same treatment `workflow-studio`, `live-operations` and `well-cockpit` already have — and is a bounded, mechanical change with no product code involved. The `frontend/tsconfig.e2e.json` project is `strict` but relaxes `noUncheckedIndexedAccess`; the journeys index into API arrays and assert on the element, and the product's own configuration keeps the rule on.
